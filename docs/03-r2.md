# Lab 3 — private objects and real downloaded integrity (35 minutes)

> **Beginner? [Use the short browser-only R2 guide](beginner-r2.md).** This page is the retained instructor/API reference.

Read [R2 theory](00-theory.md#r2-a-key-addresses-an-object-not-a-video-pipeline) and complete [setup](setup.md). **Primary route: Dashboard upload/download; optional temporary GET and direct multipart API extension.**

**Windows preferred:** browser click paths below plus built-in `Get-FileHash`. For optional native CLI operations, use [Windows PowerShell + AWS CLI](#windows-powershell--aws-cli-option), then [Windows manual multipart](05-r2-windows.md). The Bash presigning examples remain available further down. Expected result: private access paths, exact keys, source/downloaded hash equality and owned-resource cleanup.

## 1. Inspect privacy (0–5 min)

1. Dashboard → select the workshop **account** → product search **R2 object storage → Overview**. Shortcut: [R2 Overview](https://dash.cloudflare.com/?to=/:account/r2/overview).
2. Create a dedicated private bucket: **Create bucket** → copied unique legal name → approved location/jurisdiction → **Standard** → **Create bucket**. [Beginner Lab 3](beginner-r2.md) gives exact naming/settings/ownership steps. If the role is restricted, record the instructor-created group bucket or explicitly shared fallback. Record actual name, creator and jurisdiction.
3. Open the bucket → **Settings** → inspect **Public Development URL / r2.dev** and **Custom Domains**. Both public routes must be disabled/not connected for this private lab; do not change a shared production bucket.
4. Return to **Objects**. Record privacy and jurisdiction before uploading. A unique prefix is not an access-control boundary; the dedicated bucket and scoped credentials establish the stronger boundary. Never enable public access just to get a download link.

## 2. Upload and inspect exact keys (5–12 min)

1. In the bucket object view select **Create folder**, using your unique pair prefix. The slash-ending marker is a zero-byte object, not a real filesystem directory.
2. Open that prefix → **Upload → Select from computer**. In the Windows picker, open the extracted repository → `samples` → select `sample-document.txt` and `sample-video.mp4` (Ctrl-click for both) → **Open** → confirm/upload if prompted.
3. Wait for both success results → close the upload panel → refresh **Objects** → open each record. Inspect its exact case-sensitive key, size and metadata. Record `<pair-prefix>/sample-document.txt` and `<pair-prefix>/sample-video.mp4`.
4. Explain why an MP4 stored here does not acquire Stream encoding, ABR manifests or managed captions/player.

## 3. Download actual bytes and compare hashes (12–20 min)

Locate your MP4, open its **… → Download** action, and save it under a distinct local name such as `sample-video-downloaded.mp4`. Do not overwrite the source.

On Windows, choose **Save as** if offered; otherwise locate the saved file in **File Explorer → Downloads** and rename it. Browser settings may save automatically; verify the actual path before hashing. Keep the downloaded file separate from `samples\sample-video.mp4`.

Compare the source and real downloaded SHA-256:

```sh
# macOS (replace paths with your actual files)
shasum -a 256 "samples/sample-video.mp4" "sample-video-downloaded.mp4"
```

Linux: `sha256sum` with the same paths. Windows PowerShell:

```powershell
$source = (Resolve-Path '.\samples\sample-video.mp4').Path
$downloaded = "$HOME\Downloads\sample-video-downloaded.mp4" # Change to your actual saved path.
Get-Item $source, $downloaded | Select-Object Name, Length
Get-FileHash -Algorithm SHA256 -LiteralPath $source, $downloaded
if ((Get-Item $source).Length -ne (Get-Item $downloaded).Length -or
    (Get-FileHash $source -Algorithm SHA256).Hash -ne (Get-FileHash $downloaded -Algorithm SHA256).Hash) {
    throw 'Downloaded object differs from source; record the mismatch and investigate.'
}
```

Both hashes and byte sizes must match. An ETag is not the content SHA-256. This establishes the downloaded object's integrity, not a multipart-upload result. If the API extension was not run, mark multipart unperformed.

## 4. Optional: temporary GET and expiry (20–30 min)

Presigning requires SigV4 signing in a trusted terminal; this guide does not assume a Dashboard signing button or general REST endpoint. The authorized operator uses **AWS CLI v2**, as shown in official R2 docs. Participants can consume the resulting URL without installing anything.

On Windows, use [the complete AWS CLI setup/expiry commands below](#windows-powershell--aws-cli-option). The following `sh` blocks are the Bash alternative.

Privately load the dedicated bucket's S3 keys, then map them to this terminal session. Use long-lived R2 object credentials for this example, not an unrelated AWS session token:

```sh
export AWS_ACCESS_KEY_ID="$R2_ACCESS_KEY_ID"
export AWS_SECRET_ACCESS_KEY="$R2_SECRET_ACCESS_KEY"
unset AWS_SESSION_TOKEN AWS_SECURITY_TOKEN
# Set these non-secret values from your actual bucket and uploaded object.
export R2_ENDPOINT='https://REPLACE_ACCOUNT_ID.r2.cloudflarestorage.com'
export R2_BUCKET='REPLACE_BUCKET'
export R2_KEY='REPLACE_PREFIX/sample-document.txt'

R2_GET_URL=$(aws s3 presign "s3://$R2_BUCKET/$R2_KEY" \
  --endpoint-url "$R2_ENDPOINT" --region auto --expires-in 60) || exit
```

Use the matching jurisdiction endpoint for a jurisdictional bucket. Privately check that the URL has `X-Amz-Algorithm=AWS4-HMAC-SHA256`, a credential scope for `auto/s3` and `X-Amz-Expires=60`. Open it immediately in a browser or send the fresh GET below. Signing is local; only the GET tests actual existence/access.

```sh
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' "$R2_GET_URL"
sleep 65
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' "$R2_GET_URL"
```

Expected valid 2xx, then expired denial (normally 403). The same unchanged URL and GET method must be used; do not use HEAD or a custom-domain substitute. Test an unsigned S3 GET too: copy the URL's exact scheme/host/path **without query** into `R2_UNSIGNED_URL`, then use the same curl status command. It should be denied. Public-route review is still necessary. Browser JavaScript additionally needs CORS; normal navigation/terminal GET is the workshop path.

If AWS CLI is unavailable, use an instructor-generated link and record the demonstration, or mark temporary access unperformed. **[Direct S3 multipart extension](04-r2-api.md)** shows actual create/part/complete/download/abort calls with curl; an instructor can pre-stage it and show results during this block. The Dashboard does not expose manual part numbers/ETags for that exercise.

## Windows PowerShell + AWS CLI option

Use this for explicit S3 CLI calls instead of repeating the Dashboard upload. It needs **AWS CLI v2**, but no Node/npm, WSL or Python. The core Dashboard/hash lab works without AWS CLI.

### A. Install/check AWS CLI and prepare scoped S3 credentials

1. Follow the [official AWS CLI v2 Windows MSI instructions](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html#getting-started-install-instructions). Use your organization's approved install process.
2. Close and reopen PowerShell → `aws --version`. Expect `aws-cli/2...`.
3. Return to the extracted repository root as in [Windows setup](windows.md#2-download-and-find-the-samples). Paste `Read-LabSecret` from [its credential setup](windows.md#3-select-the-account-and-create-a-rest-token); R2 does not need the Images/Stream token/helper.
4. Create the bucket first. Dashboard → **R2 object storage → Overview → Account Details → Manage next to API Tokens** → **Create User API token**, or **Create Account API token** when authorized for account provisioning. [First-time setup](beginner-setup.md) explains the role, scope and once-shown secret handling.
5. Name the token for the workshop → **Object Read & Write** → scope it to the **specific dedicated bucket**, not all buckets → approved expiry → create.
6. Copy **Access Key ID** and **Secret Access Key** privately. Copy the bucket's **S3 API endpoint**; keep the chosen jurisdiction. Do not substitute the general Cloudflare REST token.

Load credentials into this PowerShell session, not a permanent AWS profile:

```powershell
$ErrorActionPreference = 'Stop'
$env:R2_BUCKET = 'REPLACE_WITH_YOUR_DEDICATED_BUCKET'
$env:PAIR_PREFIX = 'REPLACE_WITH_YOUR_UNIQUE_PREFIX'
$env:R2_ENDPOINT = 'https://REPLACE_ACCOUNT_ID.r2.cloudflarestorage.com'
$env:AWS_ACCESS_KEY_ID = Read-LabSecret 'R2 Access Key ID'
$env:AWS_SECRET_ACCESS_KEY = Read-LabSecret 'R2 Secret Access Key'
'AWS_SESSION_TOKEN','AWS_SECURITY_TOKEN' | ForEach-Object { Remove-Item "Env:$_" -ErrorAction SilentlyContinue }
$env:AWS_EC2_METADATA_DISABLED = 'true'
$env:AWS_PAGER = ''
```

Use the actual endpoint supplied for your bucket, including `.eu`, `.us` or `.fedramp` where applicable. `--region auto` does not choose jurisdiction. These examples use long-lived bucket-scoped workshop keys, not temporary AWS session credentials. Synchronize Windows time if signing reports clock skew.

Paste this local wrapper once. It adds the R2 endpoint/region, checks native exit status, and parses successful JSON. AWS CLI retains its normal request-retry behavior; the wrapper does not create buckets or repeat whole lab steps:

```powershell
function Invoke-R2Cli {
    param([Parameter(Mandatory = $true)][string[]]$ArgumentList)
    if (-not $env:R2_ENDPOINT -or -not $env:AWS_ACCESS_KEY_ID -or -not $env:AWS_SECRET_ACCESS_KEY) {
        throw 'Complete R2 Windows credential/endpoint setup first.'
    }
    $raw = & aws @ArgumentList --endpoint-url $env:R2_ENDPOINT --region auto --no-cli-pager --output json
    if ($LASTEXITCODE -ne 0) { throw 'S3 operation failed; inspect its error and stop.' }
    if ($raw) { return (($raw -join "`n") | ConvertFrom-Json) }
}
```

### B. Upload an owned key and inspect it

Skip PUT if the GUI already uploaded this same owned key; S3 PUT replaces an existing key. Record/check ownership first. This ASCII sample key avoids URL-encoding ambiguity.

```powershell
$env:R2_KEY = "$env:PAIR_PREFIX/sample-video.mp4"
$uploaded = Invoke-R2Cli -ArgumentList @('s3api', 'put-object', '--bucket', $env:R2_BUCKET,
    '--key', $env:R2_KEY, '--body', '.\samples\sample-video.mp4', '--content-type', 'video/mp4')
$metadata = Invoke-R2Cli -ArgumentList @('s3api', 'head-object', '--bucket', $env:R2_BUCKET, '--key', $env:R2_KEY)
$metadata | Select-Object ContentLength, ContentType, ETag
```

Refresh **Dashboard → your bucket → Objects**, open the exact key and compare size/content type. A PUT-created prefix need not create a separate folder-marker object.

### C. Download actual bytes and compare SHA-256

```powershell
$downloadPath = Join-Path $PWD 'sample-video-r2-cli-download.mp4'
if (Test-Path -LiteralPath $downloadPath) { throw 'Choose a fresh download filename; preserve the previous result.' }
$downloadMetadata = Invoke-R2Cli -ArgumentList @('s3api', 'get-object', '--bucket', $env:R2_BUCKET,
    '--key', $env:R2_KEY, $downloadPath)
Get-Item '.\samples\sample-video.mp4', $downloadPath | Select-Object Name, Length
$sourceHash = (Get-FileHash '.\samples\sample-video.mp4' -Algorithm SHA256).Hash
$downloadHash = (Get-FileHash $downloadPath -Algorithm SHA256).Hash
if ($sourceHash -ne $downloadHash -or
    (Get-Item '.\samples\sample-video.mp4').Length -ne (Get-Item $downloadPath).Length) {
    throw 'Downloaded object differs from the source.'
}
$sourceHash
$downloadHash
```

This verifies the downloaded object. It does not prove a multipart exercise was performed; use [the Windows manual multipart guide](05-r2-windows.md) for that evidence.

### D. Presign a GET and test expiry

Use an existing owned key. Keep the resulting URL in a private variable instead of printing it:

```powershell
$r2GetUrl = & aws s3 presign "s3://$env:R2_BUCKET/$env:R2_KEY" --endpoint-url $env:R2_ENDPOINT --region auto --expires-in 60 --no-cli-pager
if ($LASTEXITCODE -ne 0 -or -not $r2GetUrl) { throw 'Presigning failed.' }
$r2GetUrl = ([string]$r2GetUrl).Trim()
$unsignedUrl = ([Uri]$r2GetUrl).GetLeftPart([UriPartial]::Path)
curl.exe --silent --show-error --output NUL --write-out '%{http_code}\n' $unsignedUrl
curl.exe --silent --show-error --output NUL --write-out '%{http_code}\n' $r2GetUrl
Start-Sleep -Seconds 65
curl.exe --silent --show-error --output NUL --write-out '%{http_code}\n' $r2GetUrl
```

Expected unsigned denial → valid 2xx → expired denial (normally 403). `000`/native network errors are not policy results. Do not change GET to HEAD, replace the host with a custom domain, or modify the query. Signing is local; actual GETs test existence/access. Browser JavaScript additionally needs CORS; these terminal GETs do not.

### E. Cleanup the exact owned key

```powershell
$removed = Invoke-R2Cli -ArgumentList @('s3api', 'delete-object', '--bucket', $env:R2_BUCKET, '--key', $env:R2_KEY)
```

Refresh the Dashboard and verify that the key is gone. Use Dashboard to remove only an owned empty bucket after all keys and incomplete multipart uploads are cleared. Revoke only workshop credentials and follow [Windows session cleanup](windows.md#finish-and-clear-this-session).
