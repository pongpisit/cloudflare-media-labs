# Lab 3 — private objects and real downloaded integrity (35 minutes)

Read [R2 theory](00-theory.md#r2-a-key-addresses-an-object-not-a-video-pipeline) and complete [setup](setup.md). **Primary route: Dashboard upload/download; optional temporary GET and direct multipart API extension.**

## 1. Inspect privacy (0–5 min)

In **R2 object storage**, open your dedicated Standard bucket and its **Settings**. Confirm public `r2.dev` and public custom-domain access are disabled. Record bucket/jurisdiction; a unique prefix is not an access-control boundary. Never enable public access just to obtain a download URL.

## 2. Upload and inspect exact keys (5–12 min)

1. In the bucket object view select **Create folder**, using your unique pair prefix. The slash-ending marker is a zero-byte object, not a real filesystem directory.
2. Open that prefix, select **Upload**, then **select from computer** or drag/drop `samples/sample-document.txt` and `samples/sample-video.mp4`.
3. Confirm successful uploads; inspect each exact case-sensitive key, size and metadata. Record `<pair-prefix>/sample-document.txt` and `<pair-prefix>/sample-video.mp4`.
4. Explain why an MP4 stored here does not acquire Stream encoding, ABR manifests or managed captions/player.

## 3. Download actual bytes and compare hashes (12–20 min)

Locate your MP4, open its **… → Download** action, and save it under a distinct local name such as `sample-video-downloaded.mp4`. Do not overwrite the source.

Compare the source and real downloaded SHA-256:

```sh
# macOS (replace paths with your actual files)
shasum -a 256 "samples/sample-video.mp4" "sample-video-downloaded.mp4"
```

Linux: `sha256sum` with the same paths. Windows PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 "samples/sample-video.mp4", "sample-video-downloaded.mp4"
```

Both hashes and byte sizes must match. An ETag is not the content SHA-256. This establishes the downloaded object's integrity, not a multipart-upload result. If the API extension was not run, mark multipart unperformed.

## 4. Optional: temporary GET and expiry (20–30 min)

Presigning requires SigV4 signing in a trusted terminal; this guide does not assume a Dashboard signing button or general REST endpoint. The authorized operator uses **AWS CLI v2**, as shown in official R2 docs. Participants can consume the resulting URL without installing anything.

Privately load the dedicated bucket's S3 keys, then map them to this terminal session. Use long-lived R2 object credentials for this example, not an unrelated AWS session token:

```sh
export AWS_ACCESS_KEY_ID="$R2_ACCESS_KEY_ID"
export AWS_SECRET_ACCESS_KEY="$R2_SECRET_ACCESS_KEY"
unset AWS_SESSION_TOKEN AWS_SECURITY_TOKEN
# Set these non-secret values from your actual bucket and uploaded object.
export R2_ENDPOINT='https://REPLACE_ACCOUNT_ID.r2.cloudflarestorage.com'
export R2_BUCKET='REPLACE_BUCKET'
export R2_KEY='REPLACE_PREFIX/sample-document.txt'

R2_GET_URL=$(aws s3 presign "s3://$R2_BUCKET/$R2_KEY" \
  --endpoint-url "$R2_ENDPOINT" --region auto --expires-in 60) || exit
```

Use the matching jurisdiction endpoint for a jurisdictional bucket. Privately check that the URL has `X-Amz-Algorithm=AWS4-HMAC-SHA256`, a credential scope for `auto/s3` and `X-Amz-Expires=60`. Open it immediately in a browser or send the fresh GET below. Signing is local; only the GET tests actual existence/access.

```sh
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' "$R2_GET_URL"
sleep 65
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' "$R2_GET_URL"
```

Expected valid 2xx, then expired denial (normally 403). The same unchanged URL and GET method must be used; do not use HEAD or a custom-domain substitute. Test an unsigned S3 GET too: copy the URL's exact scheme/host/path **without query** into `R2_UNSIGNED_URL`, then use the same curl status command. It should be denied. Public-route review is still necessary. Browser JavaScript additionally needs CORS; normal navigation/terminal GET is the workshop path.

If AWS CLI is unavailable, use an instructor-generated link and record the demonstration, or mark temporary access unperformed. **[Direct S3 multipart extension](04-r2-api.md)** shows actual create/part/complete/download/abort calls with curl; an instructor can pre-stage it and show results during this block. The Dashboard does not expose manual part numbers/ETags for that exercise.

## 5. Explain and clean up (30–35 min)

Record privacy, exact keys, byte count/hash match and observed access statuses, with GUI/API/demonstration labels. Delete only your two objects and your zero-byte folder marker through the Dashboard. For an API extension, abort only the recorded incomplete upload and delete its completed owned key. Remove the dedicated empty bucket/revoke workshop keys if no longer needed. Clear signed links and terminal secrets.
